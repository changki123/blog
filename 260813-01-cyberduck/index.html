Cloudflare R2에 300MB 넘는 파일 올리기 — Cyberduck으로 해결하기

개인 프로젝트로 여행 영상 사이트를 만들면서 영상 파일을 Cloudflare R2에 저장하기로 했다. 그런데 R2 웹 콘솔에서 드래그앤드롭으로 파일을 올리려니 이런 에러가 떴다.

1개의 파일이 300 MB 제한을 초과하여 업로드할 수 없습니다.
더 큰 파일을 업로드하려면 S3 호환성 API 또는 Workers를 사용하십시오.

여행 영상은 대부분 300MB를 훌쩍 넘기 때문에, 웹 콘솔만으로는 업로드가 불가능했다. 이 글에서는 무료 GUI 클라이언트인 Cyberduck으로 이 문제를 해결한 과정을 정리한다.

왜 Cyberduck인가

R2는 "S3 호환 API"를 제공한다. AWS S3용으로 만들어진 통신 규격을 그대로 흉내 내서, S3 클라이언트라면 어디 회사 스토리지든 접속할 수 있게 열어둔 것이다. 그래서 서버 주소(엔드포인트)만 R2 것으로 바꿔주면, S3용 프로그램을 그대로 R2에 쓸 수 있다.

이 조건에 맞는 무료 프로그램 중 몇 가지를 비교해봤다.

  • 파일질라(FileZilla): 무료 버전은 FTP/SFTP만 지원, S3 프로토콜은 유료(Pro) 버전에서만 가능 → 제외
  • WinSCP: 최신 버전에서 S3 지원, 이미 설치되어 있다면 바로 활용 가능
  • Cyberduck: 무료, S3 프로토콜 기본 지원, Cloudflare가 공식 연결 프로필까지 배포 중 → 선택

Cyberduck을 고른 결정적인 이유는 Cloudflare가 공식 문서에서 R2 전용 연결 프로필을 따로 제공한다는 점이었다. 설정 실수를 줄일 수 있다는 뜻이라 신뢰도가 높았다.

특장점

  • 드래그앤드롭 업로드: 탐색기처럼 파일을 끌어다 놓으면 끝
  • 자동 멀티파트 업로드: 큰 파일을 자동으로 쪼개서 전송하기 때문에 300MB든 그 이상이든 제한 없이 올라간다
  • 무료: 상업적 용도가 아니면 완전 무료
  • 범용 S3 클라이언트: R2뿐 아니라 AWS S3, Backblaze B2 등 S3 호환 스토리지 전반에 쓸 수 있다

진행 과정

1. R2 API 토큰 발급

Cloudflare 대시보드 → R2 → 버킷 선택 → API 화면에서 토큰을 발급받아야 한다. 이때 몇 가지 선택할 게 있었다.

  • 계정 API 토큰 vs 사용자 API 토큰: 계정 소유권 변동에도 안 끊기는 "계정 API 토큰"을 선택했다 (프로덕션 성격에 가까운 선택)
  • 권한: "관리자 읽기 및 쓰기"가 아니라 **"개체 읽기 및 쓰기"**로 최소 권한만 부여했다. 버킷 생성/삭제 권한까지는 필요 없고, 파일 업로드/다운로드만 하면 되기 때문이다.
  • 버킷 범위: "특정 버킷에만 적용"으로 제한해서, 혹시 토큰이 유출되어도 피해 범위가 그 버킷 하나로 국한되게 했다.

토큰을 생성하면 Access Key ID, Secret Access Key, Endpoint URL이 딱 한 번만 뜬다. 창을 닫으면 Secret Access Key는 다시 볼 수 없으므로 바로 메모해둬야 한다.

2. 일반 "Amazon S3" 프로필로 시도 → 실패

처음엔 Cyberduck의 기본 "Amazon S3" 프로필로 연결을 시도했다. Server 칸에 엔드포인트 URL을 넣고 접속했더니 이런 에러가 떴다.

디렉토리 /의 목록을 얻어오는데 실패하였습니다.
Access Denied. Please contact your web hosting service provider for assistance.

원인은 주소 방식(addressing style)의 차이였다. 일반 Amazon S3 프로필은 virtual-hosted style(버킷명.도메인 형태)을 기본으로 쓰는데, R2는 path-style(도메인/버킷명 형태) 주소가 필요하다.

3. R2 전용 연결 프로필로 해결

Cloudflare가 배포하는 R2 전용 Cyberduck 프로필을 다운로드해서 더블클릭하면, Cyberduck에 "Cloudflare R2 Storage (S3)"라는 프로필이 자동 등록된다. 이 프로필은 path-style 주소가 기본값으로 설정돼 있어서, 앞서 겪은 문제가 사라진다.

그런데 이 프로필로 연결해도 여전히 같은 에러가 났다. 공식 문서에 이런 경고가 있었다.

Object Read & Write 또는 Object Read only 권한만 있고 버킷 목록 조회 권한이 없는 토큰은, 반드시 연결 설정에서 버킷 이름을 Path에 직접 지정해야 한다.

앞서 "개체 읽기 및 쓰기" 권한으로 토큰을 만들었기 때문에, 이 토큰은 "버킷이 뭐가 있는지 목록을 조회할" 권한 자체가 없다. 그래서 Path를 비워두면 Cyberduck이 "루트에 있는 모든 버킷 보여줘"라고 요청하다가 거부당하는 것이었다.

북마크 편집(Edit Bookmark) 화면에서 Path 칸에 버킷 이름을 직접 입력하니 (/버킷이름) 정상적으로 연결됐다.

4. 업로드

연결되고 나면 그 다음은 단순하다. 버킷 안으로 들어가서 영상 파일을 그대로 드래그앤드롭하면, Cyberduck이 자동으로 멀티파트 업로드로 쪼개서 전송한다. 300MB 제한 없이 몇 GB짜리 파일도 문제없이 올라갔다.

정리

문제원인해결
웹 콘솔 300MB 제한대시보드 업로드 자체 한계S3 API 지원 클라이언트(Cyberduck) 사용
Access Denied (일반 S3 프로필)virtual-hosted style 주소 방식R2 전용 Cyberduck 프로필 사용
Access Denied (R2 프로필로도 실패)최소 권한 토큰이라 버킷 목록 조회 불가북마크의 Path 칸에 버킷명 직접 지정

최소 권한 원칙(버킷 하나만, 읽기/쓰기만 허용)을 지키려다 보니 중간에 삽질이 좀 있었지만, 결과적으로는 보안과 편의성을 둘 다 챙긴 셈이 됐다. R2로 대용량 파일을 다뤄야 하는 다른 프로젝트에서도 이 조합(최소 권한 토큰 + Cyberduck + Path 지정)을 그대로 쓸 생각이다.
